# 番剧详情页三风格可切换重构设计

## 1. 目标

将现有番剧详情页重构为一个支持 **3 套完整可运行展示方案** 的详情页：

- **CINEMA**：影院海报感，优先视觉冲击
- **EDITORIAL**：日系杂志感，优先设计辨识度
- **STREAM**：流媒体平台感，优先完成度与稳定性

用户可以在 **同一详情页顶部切换** 三种方案，基于同一份数据直接比较，最终再决定保留哪一套作为正式版本。

## 2. 范围与非目标

### 范围

- 重构 `app/dashboard/(padded)/bangumi/[source]/[id]/page.tsx` 的展示层
- 新增顶部风格切换器
- 为详情页实现 3 套独立视图
- 重新组织 Hero、简介、角色、Staff 等模块的视觉与布局

### 非目标

- 不修改 Bangumi / AniList API 请求逻辑
- 不修改数据类型定义
- 不修改搜索页交互与搜索结果页结构
- 不修改关联作品的数据逻辑

## 3. 现状问题

当前详情页虽然已经拆分为 `DetailHero`、`CharacterList`、`StaffList`、`RelatedList`，但仍存在以下问题：

- 整体观感偏普通，缺少首屏记忆点
- Hero 与后续区块缺少统一的视觉叙事
- 角色、Staff 模块样式偏保守，不足以撑起详情页气质
- 页面只有一套表达方式，无法快速比较不同设计方向

## 4. 成功标准

重构完成后需满足：

1. 打开任意番剧详情页，可在顶部直接切换 **CINEMA / EDITORIAL / STREAM**
2. 三套方案不仅配色不同，且 **布局结构、阅读路径、氛围明显不同**
3. 三套方案共享同一份 `detail` 数据，不重复请求
4. 切换方案时不跳路由、不刷新页面
5. 页面在移动端与桌面端均可正常展示

## 5. 总体架构

### 5.1 页面结构

详情页将调整为：

1. **Page Shell**
   - 负责页面背景、最大宽度、整体节奏、顶部切换器
2. **Variant Switcher**
   - 在客户端维护当前方案
   - 切换 `cinema | editorial | stream`
3. **Variant Renderer**
   - 根据当前方案渲染独立视图组件
4. **Shared Atoms**
   - 少量基础原子组件/格式化逻辑共用

### 5.2 数据流

- 服务端详情页依旧只请求一次 `detail`
- 将 `detail` 传入客户端的变体容器
- 三套视图均消费同一个 `detail`
- 切换风格仅切换展示层，不触发新的数据请求

### 5.3 共用与独立边界

#### 共用

- `detail` 数据对象
- 格式化逻辑（年份、评分、状态文案等）
- 小型 UI 原子，例如：
  - 返回按钮
  - 状态徽章
  - 评分徽章
  - 标签 pill
  - 区块标题

#### 独立

- Hero 布局
- 简介模块布局
- 角色模块布局
- Staff 模块布局
- 每套方案的背景氛围系统与整体栅格

该边界用于保证三套方案差异足够大，避免“只是换皮”。

## 6. 顶部切换器设计

### 6.1 位置

- 位于详情页内容顶部
- 在首屏内清晰可见
- 作为当前详情页的控制器，而非单独实验入口

### 6.2 交互

- 形式：分段式切换器（segmented control）
- 选项：
  - `CINEMA`
  - `EDITORIAL`
  - `STREAM`
- 默认值：`CINEMA`
- 切换时不跳转路由
- 支持键盘聚焦与可见 focus 样式

### 6.3 状态管理

- 使用客户端局部状态管理当前 variant
- 初始实现无需写入 URL query
- 后续如需保留选择，可再考虑 query / localStorage

## 7. 三套视觉方案

## 7.1 CINEMA

### 目标

打造“影院海报页”质感，让用户进入页面第一眼就被主视觉击中。

### 结构

- 超大沉浸式 Banner 作为首屏主视觉
- 海报压在 Banner 与正文之间，形成视觉断层
- 标题、副标题、评分、年份、状态、标签聚合在首屏焦点区
- 简介作为次级信息板块承接 Hero
- 角色、Staff、关联作品作为往下展开的内容带

### 视觉关键词

- 深色强对比
- 高强度背景模糊与压暗遮罩
- 海报厚重阴影
- 金色或冷白高光点缀

### 优先级

- 首屏震撼感 > 信息密度

## 7.2 EDITORIAL

### 目标

打造“日系杂志编排感”，做出最有设计辨识度的一版。

### 结构

- 不沿用常规流媒体模板
- 使用不对称布局和更强版式切割
- 海报、标题、元信息、简介可能分栏排布
- 角色区更像画册卡片墙
- Staff 更偏名单式、编排式展示

### 视觉关键词

- 强排版
- 明显留白
- 信息编号/分栏/细线分割
- 更具设计作品感

### 优先级

- 设计辨识度 > 标准产品页直觉

## 7.3 STREAM

### 目标

打造最接近正式长期使用版本的一套，兼顾平台感、沉浸感与稳定浏览体验。

### 结构

- 保留强 Hero，但弱化实验性
- 信息区更加规整清晰
- 简介、角色、Staff、关联作品组织为稳定内容模块
- 阅读路径更顺，适合长期使用

### 视觉关键词

- 平台化
- 稳定
- 整洁沉浸
- 模块一致性强

### 优先级

- 完成度与耐看性 > 极端视觉实验

## 8. 模块设计原则

### 8.1 Hero

- 三套方案必须各自独立实现
- 都需要承载：
  - 返回入口
  - 主标题 / 副标题
  - 评分 / 年份 / 集数 / 状态
  - 标签
  - 海报与背景图
- 但每套在信息位置、层级、叠压关系上必须明显不同

### 8.2 简介

- 保留展开 / 收起能力
- 文案行高与可读性需优先保证
- 不同方案可拥有不同容器形态

### 8.3 角色

- 必须摆脱当前保守的小圆头像方案
- 至少在其中两套方案中使用更强的卡片视觉
- 需保留无图回退

### 8.4 Staff

- 不再只作为“普通信息列表”
- 至少在一套方案中强化其排版表现
- 需保留无头像回退

### 8.5 关联作品

- 初版可继续沿用现有数据逻辑
- 视觉上允许轻度适配每个 variant 的整体气质
- 如开发成本过高，可先保持统一实现

## 9. 文件组织建议

### 保留

- `app/dashboard/(padded)/bangumi/[source]/[id]/page.tsx`
- 现有数据获取逻辑

### 新增建议

- `components/bangumi/detail/VariantSwitcher.tsx`
- `components/bangumi/detail/BangumiDetailVariants.tsx`
- `components/bangumi/detail/views/CinemaDetailView.tsx`
- `components/bangumi/detail/views/EditorialDetailView.tsx`
- `components/bangumi/detail/views/StreamDetailView.tsx`
- `components/bangumi/detail/shared/...`

### 处理方式

- 旧的 `DetailHero`、`CharacterList`、`StaffList` 不再作为最终主结构直接使用
- 可选择保留作参考，或在重构后删除/替换

## 10. 技术实现注意点

### 10.1 Next.js

- 详情页数据请求继续保留在服务端页面中
- Variant 切换器与变体渲染器使用客户端组件承载交互状态
- 样式仍基于 Tailwind 与现有全局主题变量

### 10.2 图片

- 新实现优先使用 `next/image`
- 需确保远程图片域名与当前 `next.config.ts` 保持兼容
- 对远程图继续保证尺寸稳定，避免明显布局跳动

### 10.3 性能

- 不因为三套方案并存而重复请求数据
- 初版允许三套 UI 逻辑并存，但要避免三套都做重度图片首屏渲染副作用
- 如需要，可通过条件渲染仅挂载当前 variant

### 10.4 可访问性

- 切换器需要明确当前选中状态
- 返回按钮与主要操作元素必须保留键盘 focus 可见性
- 文本与背景对比度需可读

## 11. 验证计划

实现完成后需要至少验证：

- 同一详情页中三套方案可切换
- 不同来源（Bangumi / AniList）的详情数据都能正常显示
- 无 Banner / 无封面 / 无角色图 / 无 Staff 图时有合理回退
- 移动端与桌面端布局均不崩
- 暗色背景与浅色背景区域文本都可读

## 12. 实施顺序

1. 引入切换器与变体容器
2. 完成 CINEMA 版本
3. 完成 EDITORIAL 版本
4. 完成 STREAM 版本
5. 收口共享原子与样式一致性
6. 做最终自测并交由用户挑选正式方案

## 13. 最终交付方式

本次交付不会直接只产出一个“最终版”，而是先交付：

- 一个可切换的详情页
- 三套完整可运行的视觉版本

用户在真实页面中比较后，再决定最终保留哪一套作为正式方案。
